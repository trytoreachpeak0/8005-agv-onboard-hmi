# hmi#204 证据

本目录只放节选与汇总，不放整份日志。所有运行都在控制端本机，SDK 8.0.425，worktree `worktrees/hmi204-8005-agv-onboard-hmi`。

## 修的是什么

在途的业务报文（这里是 `SafetyStateChanged`）在写发件箱期间会话换了代，会带着旧代号写进新连接、插在新握手中间；它随后的失败又会把新会话断开。两条都早于 #197。

cs#323 那次 `HANDSHAKE_SEQUENCE_INVALID` 的来源不是这个，在服务端，见 control-server#340。

## 变异

| 名称 | 改了什么 | 模拟的失败 |
| --- | --- | --- |
| M1 | 删掉 `SendLineAsync` 里「写之前核对连接序号」 | 核对不存在 |
| M1b | `SendDurableCoreAsync` 在发送时才读连接序号 | 必填参数被传了个「此刻的值」，核对形同虚设 |
| M2 | 失败处理的条件改为恒假：一律断开 | 集成分支原来的逻辑 |
| M3 | 去掉按类型认，只按读到的会话代号判 | `bc30a54` 的判法 |
| M4 | 失败处理的条件改为恒真：一律不断开 | 新异常类型把该断的也吞了 |

「修前」是把两个产品文件用 `git restore --source bc30a54 --worktree` 换成 `bc30a54` 的样子。

## 连跑的约束

- 每种状态都 `dotnet build --no-incremental` 全量重编，并要求 `0 Error(s)`。第一次连跑时从备份还原用的 `Copy-Item` 保留了旧时间戳，MSBuild 判「不用重编」，后几种状态跑的是第一种的二进制；那一轮整轮作废、没有引用，这是重跑的那一轮。
- 每种状态跑完从备份还原两个产品文件，并核对 SHA-256 与开始时一致（日志里的 `restored OK`）。
- 「修后」三格全绿里包含对确切异常类型 `WireToGateConnectionGoneException` 的断言，只有新编出的客户端才过得了——可以据此确认没有跑旧二进制。
