# 原型 A 到生产 WPF 的映射入口

权威源：规划仓库 `.scratch/wire-to-gate-mvp/prototype/onboard-single-scenario/onboard-single-scenario-prototype.html?variant=A`。本文件只记录结构映射，不复制原型代码或假数据。

| 原型 A 结构 | 生产 WPF 落点 | 固定约束 |
| --- | --- | --- |
| 顶部车辆与四维状态 | `MainWindow` 顶部固定区；独立绑定运行、通信、业务就绪、安全/联锁 | 不合并成单一“车辆状态”；本车安全来自实时 IO |
| 左侧单场景旅程 | 固定宽度旅程列表，展示连接/取货/装货/关卡/卸货/完成及恢复状态 | 只显示 ControlServer 已承诺旅程，不显示 backlog 为当前任务 |
| 中央当前步骤 | 单一主工作区，标题、指引、权威任务事实、单一主动作 | READY/新鲜投影/安全门禁未满足时禁用；Sublot 输入共享扫码+Enter/键盘路径 |
| 右侧固定八仓 | 2×4 固定物理 1～8 号仓卡片 | 每卡分开显示业务绑定、占用三态、锁闭、输出复位、目标与 ActiveUnlockSet；仓位不因离线消失 |
| 横幅/异常入口 | 中央上方高优先级阻断区与独立本车急停入口 | UNKNOWN、断联、RECOVERY_REQUIRED 不得藏在日志或滚动区 |

目标视口为 1024×768、100% 缩放、鼠标、扫码 Enter 和普通键盘。主旅程、当前步骤、关键阻断、单一主动作和八仓必须无需危险滚动；技术日志可下钻而不占据主操作层级。现有 `MainWindow.xaml` 的顶部+扫码+4×2仓位+日志结构只作为旧基线，必须在 W2G-IS-01/02 实施时按上述三区结构重排，而不是局部换色。

状态映射必须覆盖正常、断联安全收尾、重启对账和固定范围 ExceptionRecoverySession；任何从原型 B/C 吸收的局部元素都不得改变 A 的窗口层级、旅程层级、中央单一动作和固定八仓关系。
